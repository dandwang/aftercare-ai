# 学习日志

这份日志不记录“今天看了多少课程”，而记录实际完成的能力、证据、问题和下一步。每个里程碑结束时至少更新一次。

## 使用方法

每次开发结束后，用自己的话回答：

1. 本次要解决的业务问题是什么？
2. 请求或数据经过了哪些组件？
3. 最重要的设计选择是什么，为什么？
4. 正常路径通过什么测试证明？
5. 至少一个失败路径通过什么测试证明？
6. 哪一部分仍然不理解或尚未验证？
7. 如果重新做一次，会怎样把任务描述得更清楚？

## M1：可运行骨架

**业务目标**：建立从浏览器到 Vue、FastAPI、PostgreSQL、Redis 和 Qdrant 的最小可运行链路，并区分进程存活与系统就绪。

**批准范围**：提交 M0 本地基线；创建 M1 功能分支；生成前后端和 Compose 骨架；安装并锁定依赖；不提交 M1、不 push、不创建 PR。

**数据流**：浏览器状态页请求 FastAPI `/health/ready`；API 并行探测 PostgreSQL、Redis 和 Qdrant；前端根据 HTTP 状态和结构化结果展示整体与组件状态。

**关键决定与理由**：

- `/health/live` 不访问外部依赖，避免依赖故障导致编排系统反复重启仍然正常的 API 进程。
- `/health/ready` 检查必要依赖，未就绪时返回 503，避免故障实例继续接收业务流量。
- 数据服务仅暴露在 Compose 内部网络，避免宿主机端口冲突并减少无必要的攻击面。
- TypeScript 固定为 5.9.3，因为自动选择的 7.0.2 与当前 `vue-tsc` 不兼容。

**验证证据**：

- 后端 Ruff 检查通过，Pytest 3 个测试通过。
- 前端类型检查和生产构建通过。
- Docker API、Web、PostgreSQL、Redis 均达到 healthy；Qdrant 正常运行。
- Web、live 和 ready 接口均返回 200，ready 报告三个依赖 healthy。

**失败路径**：停止 Qdrant 后，live 保持 200；ready 返回 503 并标记 Qdrant unhealthy；恢复 Qdrant 后 ready 回到 200。

**本轮发现并修复的问题**：

1. 包管理器选择了不兼容的 TypeScript 7.0.2，导致 `vue-tsc` 无法启动。通过读取错误栈定位为工具链兼容性问题，将 TypeScript 锁定为 5.9.3 后通过。
2. Web 页面可访问，但容器健康检查使用 `localhost` 时解析到 IPv6，而 Nginx 仅监听 IPv4。健康检查改为 `127.0.0.1` 后转为 healthy。
3. 宿主机 5432 已由其他项目占用。没有停止未知容器，而是移除数据库、Redis 和 Qdrant 的宿主机端口映射，仅保留内部网络连接。

**仍不理解或未验证的内容**：

- 尚未创建数据库业务模型或 Alembic 迁移。
- 尚未加入 CI；当前证据只来自本机。
- 尚未验证停止整个 Compose 环境后重新启动的数据持久化。
- 第三方测试客户端产生两个弃用警告，当前不影响行为，后续升级依赖时需要关注。

**下次怎样更好地描述任务**：明确区分宿主机端口与容器内部端口，并要求基础服务默认不暴露到宿主机。

**最终交付状态**：

- M1 已以提交 `b3f5aea`（`chore: add runnable application skeleton`）进入 `main` 并推送到远程仓库。
- 最初的功能分支方案后来根据个人学习项目的工作方式调整为直接在 `main` 串行提交；上面的“批准范围”保留为当时决策记录，不代表当前状态。
- 远程 `main` 已核对到该提交；M1 在交付时工作区干净。

## M1.5：跨任务交接机制

**业务目标**：让后续 Codex 任务不依赖某个超长对话，也能从仓库中准确理解当前进度、项目规则和下一项工作。

**批准范围**：只修正文档状态，新增仓库级 `AGENTS.md`、`docs/STATUS.md` 和 `docs/milestones/M2.md`；不修改业务代码，不提交，不推送。

**关键决定与理由**：

- `README.md` 介绍项目和稳定入口，`docs/STATUS.md` 记录随进度变化的当前事实，里程碑文档定义具体任务边界，三者职责分开。
- 根目录 `AGENTS.md` 保存每个开发任务都必须遵守的长期规则，减少在新对话里反复粘贴背景。
- 当前个人学习流程允许直接在 `main` 串行开发；一旦并行编写代码，必须改用彼此隔离的分支和 worktree。
- M2 被拆成有明确前置关系的小任务；M3 依赖 M2 的租户、鉴权和会话契约，不与 M2 主链并行实现。

**验证证据**：文档相对链接可解析，Git 差异仅包含批准的文档文件，`git diff --check` 通过。

**失败路径**：如果新任务发现工作区不干净、当前提交与 `docs/STATUS.md` 不一致，或任务需要越过已批准范围，应停止修改并先向用户说明差异。

**仍不理解或未验证的内容**：M2-A 仍是计划，数据库模型、迁移、鉴权实现和测试均尚未开始。

**下次怎样更好地描述任务**：新建任务时直接要求先读取 `AGENTS.md`、`docs/STATUS.md` 和当前里程碑文档，再只读分析目标任务。
