## 已完成任务：M2-A

目标是在不加入前端登录页面和对话功能的前提下，建立可信的最小身份基础：

- 创建租户管理员账号时，在一个事务中创建 tenant、user 和 membership。
- 使用密码登录并获得有过期时间的访问令牌。
- 使用访问令牌读取当前用户、租户和角色。
- 每次访问受保护接口时重新检查用户及成员关系是否仍然启用，使停用操作可以撤销旧令牌的权限。
- 使用 Alembic 管理数据库结构，并覆盖关键正常路径与失败路径测试。

详细范围、非范围、验收映射和执行顺序见 [M2 里程碑](milestones/M2.md)。

## 已完成任务：M2-D

- `POST /api/v1/conversations/{conversation_id}/messages/stream` 在持久化用户消息和生成中回复后，以 `started`、`delta`、`completed` 或 `cancelled` SSE 事件发送确定性回复。
- 分段写入、停止和完成都通过数据库状态条件更新；`completed` 与 `cancelled` 是终态，不相互覆盖。竞争结果以数据库提交为准；停止前已提交但尚未送达的分段可能仍在网络缓冲中，停止后不再追加持久化内容。
- 首帧也在清理保护范围内。断连、ASGI 发送失败和任务取消通过取消保护与独立事务收尾，清理最长等待 3 秒；数据库不可用或进程强制退出仍可能留下生成中记录，需按 README 的离线恢复步骤处理。
- 同一输入最多一个运行中的回复，重复重新生成返回 `409`。来源消息行锁保护版本分配；数据库保证版本号唯一、当前版本唯一，且只有已完成回复可以成为当前版本。新版本取消时保留旧当前版本。

- 后端 Ruff 通过，完整 Pytest 52 个测试通过（含 17 个真实 PostgreSQL 测试和 5 个真实 HTTP 长连接测试）；前端 17 个 Vitest 测试、类型检查与 Compose 生产镜像构建通过。

## 已完成任务：M2-E（学习演示范围）

- 新增 `conversation_summaries`、`generation_contexts` 和 `message_feedback`，由 Alembic `20261012_05` 管理，旧消息和版本保留。
- 每条新回复保存冻结的提示词、窗口消息 ID、摘要 ID、编码和计量结果。按用户输入顺序选择其唯一已完成当前回复；重新生成旧输入时排除该输入的所有助手版本及后续轮次。
