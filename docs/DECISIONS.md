# 架构决策记录

本文件记录会影响后续实现的重要选择。新的重大选择应追加记录，不通过悄悄改代码改变既有边界。

## ADR-001：采用模块化单体

- **状态**：Accepted
- **背景**：第一版需要同时交付身份、对话、RAG、Tool、工单和部署能力，但只有一个学习者维护。
- **决定**：前端使用一个 Vue 应用；后端使用一个 FastAPI 部署单元，并按业务模块划分内部边界。后台任务使用独立 Worker 进程，但共享后端领域代码和数据库模型。
- **理由**：便于本地启动、事务处理、调试和部署，同时仍能学习清晰边界。
- **代价**：模块不能独立扩缩容；若未来拆分服务，需要重新设计跨模块事务和接口。

## ADR-002：第一版在 Qdrant 中完成混合检索

- **状态**：Accepted
- **背景**：阶段目标要求语义与关键词混合检索。第一版同时维护 Qdrant 和 Elasticsearch 会增加部署、同步和排障成本。
- **决定**：在 Qdrant 中保存 Dense 和 Sparse 表示，通过融合召回后执行 Rerank。PostgreSQL 保存文档生命周期的权威状态。
- **理由**：用一个检索服务完成首版学习目标，减少跨索引一致性问题。
- **代价**：不会在第一版深入学习 Elasticsearch/OpenSearch；如果后续出现复杂全文分析需求，再用评测数据决定是否引入。

## ADR-003：只实现一个受控 Agent

- **状态**：Accepted
- **背景**：核心流程需要在知识检索、业务 Tool 和人工服务之间路由，但不需要多个自治 Agent 协商。
- **决定**：使用 LangGraph 实现一个节点明确、步骤有上限、状态可持久化的工作流。
- **理由**：可以学习状态、Checkpoint、Tool 和恢复，同时保持行为可测试。
- **代价**：复杂流程需要显式增加节点，不能依靠多个 Agent 自由协作解决。

## ADR-004：业务系统使用模拟数据

- **状态**：Accepted
- **背景**：学习项目不应操作真实订单、支付、退款或客户隐私数据。
- **决定**：在 PostgreSQL 中构造模拟订单、物流、退款和工单；Tool 接口按未来外部集成边界设计。
- **理由**：保留真实的权限、事务、幂等和失败语义，同时避免外部账号、合规和资金风险。
- **代价**：项目不能证明某一真实电商平台的集成细节，需要在未来集成时补充适配层和契约测试。

## ADR-005：受控 Beta 使用单机 Docker Compose

- **状态**：Accepted
- **背景**：第一版的重点是完整上线链路，而不是 Kubernetes 运维。
- **决定**：使用一台 Linux 服务器和 Docker Compose 部署，配合 HTTPS、健康检查、持久化卷、备份和回滚步骤。
- **理由**：在较低基础设施复杂度下学习镜像、迁移、部署和恢复。
- **代价**：单机存在可用性上限，不适合作为大规模或严格高可用方案。

## ADR-006：Compose API 启动前执行 Alembic 升级

- **状态**：Accepted
- **背景**：M2-A 引入持久化身份数据后，API 若在空数据库或旧结构上启动，会在首个认证请求时失败。
- **候选方案**：由开发者手动执行迁移；在 Compose 中增加独立迁移服务；由单机 Compose 的 API 启动命令执行迁移。
- **决定**：当前受控 Beta 的单机 Compose 环境中，API 容器先执行 `alembic upgrade head`，成功后才启动 Uvicorn。生产部署前仍需将迁移作为独立、可观测的部署步骤重新评估。
- **理由**：本地环境可以从空数据库重复启动，且迁移失败会阻止新 API 进程变为健康状态。
- **代价**：未来多副本部署不能沿用此做法，否则并发启动可能竞争迁移锁；必须改为单独的迁移步骤或 Job。
- **验证方式**：在 Docker Compose PostgreSQL 上演练 `upgrade → downgrade → upgrade`，再验证 API 健康检查和认证接口。

## 新 ADR 模板

```markdown
## ADR-NNN：标题

- **状态**：Proposed / Accepted / Superseded
- **背景**：为什么需要做决定？
- **候选方案**：考虑过哪些选择？
- **决定**：最终选择什么？
- **理由**：为什么？
- **代价**：失去了什么，新增了哪些风险？
- **验证方式**：用什么数据或测试判断决定是否正确？
```
